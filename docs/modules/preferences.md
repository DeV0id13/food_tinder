# FT-03 — preferences

Модуль `preferences` реализует пользовательское состояние рецептов: лайки, суточные дизлайки, избранное и персональную ленту.

## Файлы

- `apps/preferences/models.py` — модель `UserRecipeState` и уникальность `(user, recipe)`.
- `apps/preferences/serializers.py` — `RecipeSummary`, `RecipeState` и входные serializers.
- `apps/preferences/services.py` — транзакции свайпов, отмены и закладок с блокировкой пользователя.
- `apps/preferences/views.py` — feed, swipes, favorite и favorites.
- `apps/preferences/selectors.py` — одиночная и пакетная проверка избранного для planning.
- `apps/preferences/urls.py` — маршруты FT-03.
- `apps/preferences/migrations/0001_initial.py` — миграция состояния пользователя.
- `tests/preferences/` — API-тесты и отдельный тестовый URLConf.

## Интеграция

API подключён в `config/urls.py`:

```text
path("api/v1/preferences/", include("apps.preferences.urls")),
```

Миграция `apps/preferences/migrations/0001_initial.py` зависит от:

```python
("catalog", "0001_initial")
```

и от текущей модели пользователя через `settings.AUTH_USER_MODEL`.

Для локальных тестов используется отдельный `tests/preferences/urls.py`, поэтому корневой URLConf проекта изменять для тестирования FT-03 не требуется.

## API

Доступны следующие endpoints:

- `GET /api/v1/preferences/feed/` — публичная персонализированная лента; для гостя возвращает все активные рецепты без пользовательских исключений.
- `POST /api/v1/preferences/swipes/` — сохранить `like` или `dislike`; ответ содержит состояние и `undo_token`.
- `POST /api/v1/preferences/swipes/undo/` — принять JSON `{"undo_token": "<uuid>"}` и вернуть восстановленное состояние (200).
- `PUT /api/v1/preferences/favorites/<recipe_id>/` — добавить или удалить рецепт из избранного; требуется аутентификация.
- `GET /api/v1/preferences/favorites/` — список активных избранных рецептов текущего пользователя; требуется аутентификация.

`feed` и `favorites` используют стандартный DRF `LimitOffsetPagination`:

- `limit=30` по умолчанию;
- максимальный `limit=100`;
- `offset=0` по умолчанию;
- `next` и `previous` содержат URL либо `null`.

## Поведение

При свайпе `LastSwipe` сохраняет предыдущие `liked_at`, `disliked_until` и `is_favorite`
в той же транзакции. Если до свайпа состояния не было, отмена удаляет созданную запись.
Хранится один последний свайп на аккаунт, привязанный к Django-сессии, которая его сделала.
Токен действует пять секунд. Новый свайп в любой сессии, изменение закладки того же рецепта
или успешная отмена делают предыдущий токен недействительным (409). Другой аккаунт или
другая сессия с тем же токеном также получают 409. Запрос требует сессию и CSRF.

Миграция `0003_lastswipe` создаёт таблицу снимков. При откате миграции пропадает возможность
отменить сохранённый свайп. Уже сохранённые состояния рецептов остаются в `UserRecipeState`.

- `like` сохраняет первое значение `liked_at`, добавляет рецепт в избранное (`is_favorite=True`) в той же транзакции; повторный like не меняет исходный timestamp.
- Миграция `0002_favorite_existing_likes` однократно переносит старые лайки в избранное; существующие записи без лайка не затрагиваются.
- `like` снимает активный dislike.
- `dislike` действует до следующей полуночи UTC.
- Истёкший `disliked_until` не удаляется из БД, но больше не влияет на feed.
- `dislike` не меняет признак избранного.
- `favorite` не изменяет `liked_at` и `disliked_until`.
- Удаление из избранного сохраняет остальные состояния рецепта.
- Лайк или дизлайк неактивного рецепта возвращает `404`.
- Неактивный рецепт нельзя добавить в избранное, но существующую отметку избранного можно снять.
- Feed авторизованного пользователя исключает его лайкнутые рецепты и рецепты с активным dislike.
- Состояния разных пользователей полностью изолированы.
- Добавление рецепта в избранное само по себе не скрывает его из feed.
- `feed` и `favorites` сортируются по `recipe.id` по возрастанию.
- Неизвестные поля write-запросов, включая `user_id`, отклоняются с `400`.
- `is_favorite` принимает только настоящий JSON boolean: `true` или `false`.

## Чтение из planning

Обработчик записи одного слота вызывает:

```python
is_favorite(*, user_id: int, recipe_id: int) -> bool
```

При пакетном сохранении редактор вызывает `favorite_recipe_ids(*, user_id, recipe_ids)`
для новых или заменённых рецептов. Обе функции читают состояние текущего пользователя.

## FT-10. Срок отмены и дата добавления в избранное

`POST /api/v1/preferences/swipes/` возвращает `undo_token` и
`undo_remaining_ms`. Отмена доступна пять секунд с момента записи свайпа.
Запрос проверяет последний токен, владельца и сессию. На границе пяти секунд,
для старого токена до миграции и при повторном использовании сервер возвращает
HTTP 409. При успешной отмене восстанавливаются также прежняя дата добавления
в избранное и состояние закладки.

В элементах `GET /api/v1/preferences/favorites/` появилось поле `favorited_at`.
Оно обновляется при добавлении закладки или лайке, который добавил рецепт в
избранное. Повторная закладка не меняет дату. Для старых записей миграция
`preferences.0004` подставляет дату лайка, если она известна. Старые закладки
без лайка получают значение `null` и идут после записей с известной датой
при сортировке по добавлению.
