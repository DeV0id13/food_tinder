# FT-11 — Автоподбор блюд из избранного

Автозаполнение выполняется **локально** в существующем редакторе рациона; новый backend,
OpenAI API и дополнительная схема PostgreSQL для этого не требуются.

1. Выберите дату, длительность 1/3/7, приёмы пищи и количество человек (1–20).
2. «Заполнить пустые слоты» оставляет все уже вручную выбранные блюда и порции.
3. Алгоритм берёт только `favorites` текущего авторизованного пользователя и
   назначает блюда лишь на совместимые с `meal_types` слоты.
4. Он минимизирует повторы, особенно в пределах одного дня, и старается не
   повторять те же рецепты в соседние дни; при нехватке вариантов
   допускаются повторы. Если для приёма пищи вообще нет рецептов,
   слот остаётся пустым и появляется объяснение.
5. «Пересобрать меню» с подтверждением заменяет слоты текущего черновика;
   следующая генерация изменяет детерминированную ротацию рецептов.
6. После подбора любой рецепт и число порций можно изменить существующим
   визуальным picker.
7. Все изменения до «Сохранить рацион» остаются локальным черновиком,
   привязанным к пользователю. API записи в этот момент не вызывается;
   сработает прежний атомарный `POST/PUT /api/v1/meal-plans/` только по кнопке Save.

Ограничения: при недостатке избранных блюд не обещаем полного разнообразия,
не выбираем рецепты вне избранного, не делаем расчёт пищевой ценности и
не отправляем предпочтения третьим сторонам.

Новые тесты `frontend/tests/auto-plan.test.mjs` проверяют совместимость,
повторы, сохранность текущих слотов, отсутствие изменения входного плана
и пересборку меню. Сквозной frontend-тест отдельно проверяет, что запросы
сохранения не выполняются при генерации.
