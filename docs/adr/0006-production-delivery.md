# 0006. Образы по SHA и подтверждение deploy

**Контекст.** Production VM располагает 2 ГБ памяти. Обновление должно использовать
проверенные зависимости, образы и код одного коммита.

**Решение.** GitHub-hosted runners собирают образы и публикуют их в GHCR под SHA
при push в `master`. Trivy блокирует публикацию backend при критических
результатах. Deploy ждёт семь jobs и подтверждение окружения `production`.
VM скачивает образы, применяет миграции и static, обновляет сервисы и проверяет
готовность.

**Альтернативы.** Сборка на VM расходует её ограниченную память. Плавающий тег
затрудняет привязку к проверенному коммиту. Автоматический deploy убирает
ручную точку управления обновлением.

**Последствия.** Выпуск можно однозначно связать с репозиторием и образами.
Deploy требует настроенных разрешений и подтверждения, а миграции применяются
в стандартном окне обновления.
