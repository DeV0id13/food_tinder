# 0004. Атомарное редактирование рационов

**Контекст.** Пользователь редактирует набор слотов локально. Сетевой повтор и
параллельная вкладка могут попытаться сохранить один план одновременно.

**Решение.** POST с `creation_key` связывает содержимое и ключ хешем. В транзакции
сначала блокируется пользователь. PUT блокирует принадлежащий пользователю план
и сохраняет итоговый набор с проверкой `version`. Повтор уже применённого
запроса с тем же содержимым возвращает текущий результат, несовместимость даёт
409. Изменения слотов и инвалидация устаревших покупок фиксируются вместе.

**Альтернативы.** Независимые PUT каждого слота пригодны для одиночной операции.
При сохранении всего редактора они допускают частично влияющие записи.
Стратегия без проверки версии могла бы затереть правку другой вкладки.

**Последствия.** Клиент сохраняет ключ и версию в черновике и обрабатывает 409.
Блокировки действуют на один план, а идемпотентное создание сериализуется
для одного владельца.
