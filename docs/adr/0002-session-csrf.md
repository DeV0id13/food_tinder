# 0002. Django sessions и CSRF

**Контекст.** Caddy обслуживает UI и API на одном origin. Admin и приложение
используют одну модель пользователя.

**Решение.** Django хранит сессию на сервере, браузер передаёт HttpOnly cookie.
DRF проверяет сессию и CSRF для записей. Гостевые login, register и logout
также явно защищены CSRF. Клиент читает токен перед запросом, поскольку
Django обновляет его при входе.

**Альтернативы.** JWT удобен при нескольких самостоятельных клиентах и
сервисах. Для этого браузерного приложения его применение добавило бы
управление доступом, обновлением и отзывом токенов.

**Последствия.** Сессии отзываются стандартными средствами Django, пароль
и идентификатор сессии не хранятся в browser storage. Клиенты API должны
корректно передавать cookies, origin и актуальный `X-CSRFToken`.
