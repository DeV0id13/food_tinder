# FoodTinder: запуск скачанного прототипа

В архиве — полный frontend текущего прототипа: HTML, CSS, JavaScript, 12 тестовых рецептов, фотографии, шрифты и тесты. Отдельного backend, Django API и PostgreSQL в этой версии нет. Все расчёты выполняются в браузере, изменения сохраняются в localStorage.

## Windows / PowerShell

1. Распакуйте архив и откройте папку `FoodTinder-source` в PyCharm или терминале.
2. Если установлен Python 3, выполните из этой папки:

```powershell
py -m http.server 4173 --bind 127.0.0.1 --directory public
```

Если команда `py` недоступна, используйте `python` вместо `py`.
3. Откройте http://localhost:4173 в браузере.
4. Для остановки сервера нажмите Ctrl+C в терминале.

## macOS / Linux

```bash
python3 -m http.server 4173 --bind 127.0.0.1 --directory public
```

Страница должна открываться через локальный HTTP-сервер. Открытие `index.html` двойным щелчком не подходит для JavaScript-модулей.

Для запуска frontend не требуется Node.js, установка npm-пакетов или подключение к внешним сервисам. Python здесь только раздаёт файлы и не является backend приложения.

## Что где лежит

- `public/index.html` — страница приложения.
- `public/style.css` — оформление и адаптивная вёрстка.
- `public/app.js` — интерфейс и пользовательские взаимодействия.
- `public/data.js` — рецепты, ингредиенты и шаги приготовления.
- `public/domain.js` — расчёты списка покупок, автозаполнение и обработка состояния.
- `public/assets/` — изображения, шрифты, иконка и лицензия шрифта.
- `tests/domain.test.mjs` — проверки расчётов.
- `tests/e2e.mjs` — сквозная браузерная проверка.
- `build.mjs` — копирование frontend в `dist/` для отдельного размещения.
- `README.md` — описание возможностей и источники изображений.

## Тесты и сборка (необязательно)

Нужен Node.js 22 или новее.

```bash
npm test
npm run build
```

Для браузерных тестов дополнительно установите Playwright:

```bash
npm install --no-save playwright
npx playwright install chromium
node tests/e2e.mjs
```

## Данные и доступ

Локальная копия и размещённый сайт — разные адреса: сохранённые в браузере рационы не переносятся между ними автоматически. В архив включён исходный набор рецептов, без пользовательского состояния.

Приватный вход размещённого сайта обеспечивается платформой Sites. Этот механизм хостинга не входит в скачиваемый код. Приведённая команда запуска слушает только локальный компьютер (127.0.0.1).

При подключении к Django + PostgreSQL следует перенести хранение рецептов, избранного, рациона и пользователей в API. Модуль расчётов `public/domain.js` помогает увидеть текущие правила суммирования и порций; интерфейс можно сохранить.
